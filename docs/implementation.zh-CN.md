# 技术实现说明

[English](implementation.md) · **简体中文**

本文介绍浏览器中的渲染与导出管线、实现限制及开发检查。产品功能和本地运行方式见 [README](../README.zh-CN.md)。

## 画面来源与渲染

摄像头和演示视频实现同一套 `FrameSource` 接口，提供当前图像、尺寸及就绪状态。一个主渲染循环读取当前来源。摄像头优先使用 `requestVideoFrameCallback`，不支持时回退到 `requestAnimationFrame`；演示视频使用限速至 30 fps 的 `requestAnimationFrame`。

渲染器先将图像采样到「列数 × 行数」的小画布。行数由来源宽高比与实测字宽共同计算，保留画面比例。镜像作用于图像采样，字符本身不会翻转。冻结保存来源帧，仍可继续调整效果；对比两侧读取同一帧。

每格计算 BT.601 明度；自动色阶使用直方图 2% / 98% 分位点并做帧间平滑，之后再应用手动对比度和亮度。查找表把色调映射为字符与颜色。黑白模式每行绘制一串文字；原色和调色板模式通过 `source-in` 为白色文字层着色，调色板使用缓存的 256 级 OKLCH 渐变。

字符梯度从暗到亮排列。二进制和矩阵数字按实测笔画面积排序，空格作为最暗一级。自定义梯度接受 2–64 个有效字符，过滤不支持或过宽的字形、重复项和控制字符；输入无效时继续使用最后一个有效梯度。方块模式使用 Unicode 块元素，对齐效果取决于系统字体。

六张预设卡片共享一路演示视频解码。每次预览刷新只把当前帧缩小一次，放入共享的 240 × 135 画布。卡片渲染使用各预设 40% 的列数，通常以 10 fps 刷新，负载较高时降低至 4 fps；离开视口的卡片和后台标签页暂停预览。预设参数定义在 [presets.ts](../src/ascii/presets.ts)。

## 摄像头与界面生命周期

开启、停止、错误、卸载和离页会递增会话编号。异步摄像头操作在每个 await 后检查编号，释放过期请求取得的流。设备切换先打开新摄像头，再释放旧摄像头；驱动不支持同时打开时，释放后重试，必要时尝试恢复原设备。设备切换之外的轨道结束会返回演示画面。

iOS 可能在打开另一摄像头时结束旧轨道，详见 [WebKit 的摄像头并发说明](https://bugs.webkit.org/show_bug.cgi?id=264288)。切换过程保留旧流引用，避免它的 `ended` 事件取消新请求；已被替换的旧流事件也不会影响当前流。如果请求失败时旧流已结束，即使错误通常表示设备不可用，也会进入释放、重试和恢复路径。设备选择使用枚举取得的 `deviceId` 精确约束；默认开启偏好 `facingMode: user`，不同时添加互相冲突的朝向与设备约束。物理及组合镜头是否可用仍取决于浏览器和设备。

React 管理界面与低频状态，参数通过 ref 传递给渲染器。语言切换更新文字，不替换正在使用的摄像头或录制器。摄像头和演示画面共用对比、冻结及导出路径。

## 采集与录制

PNG 读取最终画布的当前像素尺寸。采集请求保存对应尺寸，并通过代次标记阻止页面清理后才返回的图片回调触发下载。

视频使用独立录制画布，尺寸为偶数，最高 1920 × 1080。尺寸在开始录制时固定；窗口、全屏或画面来源变化后等比缩放，必要时补黑边。目标时间轴为 30 fps，使用 `captureStream(0)` 和显式 `requestFrame()` 提交，缺少支持时回退到定时采集。浏览器调度与编码负载仍可能造成帧延迟。

MediaRecorder 提供 MP4 / H.264 或 WebM / VP9，可用格式候选还包括 VP8 和浏览器默认编码。视频码率按尺寸估算为 2.5–12 Mbps，不含音频。视频与 GIF 录制互斥，录制期间锁定摄像头设备切换。

### 容器收尾

收尾器面向本应用产生的单视频轨录制，不是任意媒体转换工具。原始编码样本保持不变，不重新编码。

- **MP4：** 将分片输出整理为 `ftyp | moov | mdat`，保留编码配置，重建时间、样本位置及同步样本表。检查盒边界、字段计数、整数范围及样本是否位于真实 `mdat` 载荷内。普通 MP4 可以原样返回。
- **WebM：** 写入已知 Segment / Cluster 长度、Duration、SeekHead 和 Cues。Cluster 载荷保持不变，Cue 指向以关键帧开头的 Cluster；无效长度、时间比例和时间戳会使改写终止。

收尾失败时返回原始录像，并用当前语言提示时长或定位可能受限。这保留已有数据，不能修复损坏的源录像。MP4 通过媒体片段组合，避免把全部载荷读入内存；WebM 需要读取整个文件，峰值内存约为文件大小的 2–3 倍。长时间录制优先使用 MP4；如果内存压力导致浏览器直接结束标签页，无法保证交付降级文件。

### GIF 与清理

GIF 按 10 fps 采样，最长 10 秒，最大宽度 640 px，每帧最多 256 色。像素缓冲以 Transferable 形式交给 Web Worker 编码。主线程保留一帧计算显示时长；较慢设备的 Worker 消息队列仍可能积累。

完成、取消、错误和离页会清理录制资源、终止 Worker。截图 Blob URL 在下载开始后短暂保留再释放；视频和 GIF URL 保留至被替换、关闭或页面清理。

## 源码结构

| 路径 | 用途 |
| --- | --- |
| `src/ascii/` | 渲染器、字形测量、字符梯度、调色板和预设 |
| `src/camera/`、`src/media/`、`src/demo/` | 摄像头生命周期、统一画面接口与演示源 |
| `src/presets/` | 共享动态预设预览 |
| `src/export/` | 采集、录制器、容器收尾与 GIF Worker |
| `src/hooks/`、`src/components/`、`src/i18n/` | 界面生命周期、控制组件和翻译 |
| `tests/` | MP4 / WebM 测试及录制样本 |
| `tools/audit/` | 浏览器、媒体与第三方分发检查 |
| `public/vendor/` | 第三方对应源码、许可证及版权通知 |

## 开发检查

```bash
npm test
npm run typecheck
npm run lint
npm run build
node tools/audit/verify-third-party.mjs
```

单元测试使用 Chrome MediaRecorder 样本和独立解析器，检查输出结构、编码字节保留、时间戳、定位索引、重复收尾及损坏输入降级。样本覆盖单轨 H.264 / VP9，不涵盖所有浏览器容器变体。

[本地复验指南](../tools/audit/README.md)介绍生产构建浏览器检查、虚拟摄像头、FFmpeg 解码与定位、第三方源码验证。桌面自动化和模拟移动布局不能证明真实设备的摄像头及相册兼容性。设备测试方式见[本地 HTTPS 指南](mobile-testing.zh-CN.md)。
