# ASCII Camera 项目需求基线

> 本文件是项目内的需求基线，用于在各开发阶段对照范围。
> 产品定位与阶段划分由项目负责人确定；新增产品功能须经项目负责人确认后再写入本文件。

## 1. 项目定位

一个打开网页就能玩的实时 ASCII 摄像头。

**正式定位：B 为主要定位，A 为基础能力。**

- **B：创意型实时视觉玩具**：强调即时体验、视觉风格、实时交互、趣味性和作品创作。
- **A：实用型 ASCII 工具**：提供稳定的图像转换、参数控制、截图、录制和导出能力。

用户打开网页后应当立即看到实际效果（演示模式，无需授权摄像头），切换预设就能感受到不同的视觉风格，并且能够直接录制和导出作品。所有画面只在本地浏览器中处理。

这是一个需要真实使用的独立产品，不是一次性代码演示：优先保证核心体验和工程可靠性，不为了展示技术而过度设计。

## 2. 完整功能清单

| 类别 | 功能 | 阶段 |
| --- | --- | --- |
| 演示模式 | 首次打开自动播放雕塑演示视频，不申请摄像头；摄像头未运行 / 启动中 / 停止 / 失败时都显示演示动画 | 3.2 |

| 摄像头 | 异常提示：权限被拒绝、无可用摄像头、摄像头被占用或无法读取、浏览器不支持（同时继续显示演示动画） | 1、3.2 |

所有风格、调色板、预设与参数调整立即生效，不重新申请摄像头权限，不重新启动视频流，不新建渲染循环，不中断录制。

## 3. 非目标

- 不引入 Next.js、Tailwind、UI 组件库
- 不引入后端、数据库、AI API、用户账号或云存储
- 不上传摄像头画面、演示素材、截图或录制文件；不加载远程演示素材
- 不请求麦克风权限，不录制音频
- 不为每个字符创建 DOM 元素
- 不使用真实人物肖像或第三方 IP；演示素材只用项目负责人指定的一段视频，不制作多段演示素材，不提供素材选择器
- 不实现用户自定义预设的保存、导入和管理
- 不部署，不进行远程上传（当前采用纯本地开发）
- 不再扩展已完成的双语国际化和最终 UI / 美术设计（功能冻结）
- 不为追求更高字符密度而牺牲实时性
- 不新增未经项目负责人确认的功能或控制项

## 4. 技术约束

- Vite + React + TypeScript + Canvas 2D；包管理器 npm；Node.js 22.22.1（`.nvmrc`）
- 运行时依赖：React（MIT）、gifenc 1.0.3（包声明 MIT，PNN 派生量化器按 MPL-2.0 提供对应源码及通知）；视频容器收尾由项目自带代码完成，不重新编码
- React 只管理 UI 与低频状态，不每帧触发 React 状态更新（包括预设预览）
- 统一画面来源（FrameSource）：摄像头与演示动画进入同一条渲染管线；任何时刻最多一个主渲染循环
- 可见画布即最终合成画布，是屏幕显示、全屏、PNG、MP4 / WebM、GIF 的唯一来源
- 预设预览：共享同一演示视频（一路解码，时间基准为视频播放进度），每张卡片独立的小尺寸渲染器（≤240×135），默认 10 FPS 并自适应降帧，离开视口或页面进入后台时暂停；主预览优先
- 启停、切换设备、演示 / 摄像头切换、冻结 / 恢复、模式与参数调整、录制、组件卸载、页面离开，均不得产生重复渲染循环，也不得泄漏摄像头、录制流、Worker 或 Blob URL

## 5. 开发阶段与职责

### Phase 1：最小可玩原型

打通“摄像头 → 实时字符画”的核心链路，保证摄像头生命周期可靠。

### Phase 2：完整核心功能

视觉模式、字符密度、亮度、对比度、全屏，以及自动色阶与手动参数的兼容。

### Phase 3：Creative Experience & Export

原画 / ASCII 对比、PNG / WebM / GIF 导出、字符集与自定义字符梯度、冻结 / 恢复、摄像头选择、统一的最终画面输出、界面分组。

### Phase 3.2：Look Presets & Demo Experience（最后一轮核心功能扩展）

渐变调色板系统（三种最终视觉模式）、六种效果预设及其动态预览、全产品唯一的演示素材（本阶段为原创 Canvas 角色，Phase 5.2 起由项目负责人提供的雕塑视频替代）、无摄像头时自动运行的演示模式、统一画面来源架构。本轮完成后核心功能原则上冻结。

### Phase 4 至 Phase 6.3.2

已完成双语国际化、最终 UI / UX、移动端与 iPhone 沉浸式预览、正式雕塑演示素材及展示材料。当前为 Phase 06.3.2 正式 Git 封板阶段；功能冻结，负责人已授权精确暂存、正式提交、合并 main 及推送 GitHub。本阶段不创建 Tag / Release 或部署。

## 7. 关键实现约定

- **图像处理顺序**：原始明度 → 自动色阶（只根据原始画面统计黑白点）→ 对比度（以中灰为中心缩放）→ 亮度（整体平移）→ 字符映射 → 视觉模式 / 调色板。三种视觉模式共用这一条处理链；颜色不影响字符密度。
- **调色板**：色调 0 / 127.5 / 255 分别对应暗部 / 中间调 / 高光颜色，在 OKLCH 中插值，调色板变化时预计算 256 级 RGB 查找表。Matrix Green 的节点取自原绿色终端公式，迁移前后差异由视觉回归测试验证。
- **字符梯度方向**：所有字符集按“从暗到亮”排列；Binary / Matrix 中数字的先后按实际字形笔画面积排序，并以空格作为最暗一级。
- **效果预设**：只写入视觉模式、字符集、调色板（调色板模式时）、密度、亮度、对比度。当前配置与某个预设完全一致时显示该预设，否则显示“已手动调整”；自定义调色板或自定义字符梯度不属于任何预设。
- **演示素材**（Phase 5.2 起）：雕塑视频，每个新视频帧复制到帧画布一次；静音、循环、playsinline；页面隐藏时暂停；自动播放被拦截时显示首帧并在首次交互后播放；加载失败时使用海报帧。早期 Phase 3.2 的 Canvas 程序绘制素材已移除。
- **同帧保证**：对比模式下每帧先复制画面来源的当前帧，字符采样和原画都从副本读取；冻结时以冻结帧为唯一画面来源。
- **导出边界**：分割线绘制在作品中；拖动手柄、标签、REC / 冻结 / DEMO 标记属于网页界面，不进入作品。
- **录制冲突**：视频录制与 GIF 录制互斥；录制期间禁止切换摄像头设备；录制期间开启 / 停止摄像头（在摄像头与演示动画之间切换）不中断录制；离开页面时放弃录制并释放全部资源。
